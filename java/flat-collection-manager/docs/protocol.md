# Протокол обмена

Клиент и сервер обмениваются сообщениями по TCP. Одно соединение несёт один запрос и один ответ, после ответа сервер закрывает соединение.

## Кадр

| Поле | Размер | Описание |
|---|---|---|
| длина | 4 байта, big-endian | размер полезной нагрузки в байтах |
| нагрузка | `длина` байт | сериализованный объект `Request` (клиент) или `Response` (сервер) |

Допустимая длина: от 1 до 65 536 байт для запроса и от 1 до 33 554 432 байт для ответа. Сервер закрывает соединение без ответа, если длина вне диапазона, сообщение не удалось прочитать или клиент не прислал запрос за 10 секунд.

## Request

| Поле | Тип | Описание |
|---|---|---|
| `login` | `String` | логин, может быть `null` до входа |
| `password` | `String` | пароль, отправляется с каждым запросом |
| `type` | `CommandType` | команда |
| `argument` | `String` | аргумент из строки команды (`id`, начало названия), иначе `null` |
| `element` | `FlatDraft` | квартира для команд `add`, `update`, `add_if_min`, `remove_greater`, `remove_lower`, иначе `null` |

`FlatDraft` не содержит ни `id`, ни владельца, ни даты создания: их назначает сервер. Клиент не может выдать чужую квартиру за свою или подменить дату.

`toString()` запроса заменяет пароль на `***`, чтобы он не попал в журнал.

## Response

| Поле | Тип | Описание |
|---|---|---|
| `status` | `Status` | `OK`, `ERROR`, `AUTH_REQUIRED`, `FORBIDDEN`, `NOT_FOUND` |
| `message` | `String` | текст для пользователя |
| `flats` | `List<Flat>` | элементы коллекции, отсортированные по названию; пустой список, если команда их не возвращает |

## Десериализация

Сообщение приходит из сети и может быть подделано, поэтому `Wire.decode` применяет `ObjectInputFilter`:

```
flats.common.**; java.lang.*; java.util.ArrayList; java.time.*; java.time.zone.*; !*
maxdepth=20; maxrefs=500000; maxbytes=<лимит сообщения>
```

Любой класс вне списка отклоняется до создания объекта. После чтения проверяется, что объект имеет ожидаемый тип.

## Порядок и идемпотентность

Подключение клиент повторяет до трёх раз с паузой 0,5 и 1 секунда. После того как запрос отправлен, повторов нет: если оборвётся только ответ, повтор `add` создал бы вторую квартиру. Клиент в таком случае сообщает об ошибке связи, и пользователь проверяет результат командой `show`.
