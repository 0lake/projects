# Триггер статусов

Задача: статус каждого участника сцены (человек, пингвин, существо) должен автоматически отражать, кто находится с ним в одном месте.

| Состав в месте | Человек | Пингвин | Существо |
|---|---|---|---|
| Только существо | | | в поисках жертвы |
| Человек и пингвин | в группе с пингвином | в группе с человеком | |
| Существо и кто-то ещё | догнан существом | догнан существом | жертва поймана |
| Один участник | в одиночестве | в одиночестве | |

## Почему не исходная реализация

Первая версия (из учебной работы) содержала проблемы, которые видны при запуске на реальных данных:

1. Триггер срабатывал только для нового местоположения. Когда участник уходил, прежнее место не пересчитывалось, и оставшиеся сохраняли устаревший статус.
2. Проверка «человек и существо» выполнялась по таблице `Human` без проверки наличия существа: любой человек в месте получал статус «догнан существом».
3. Порядок проверок определял результат: поздние `UPDATE` затирали ранние.
4. Таблицы не имели столбца `status` и существа не имели `current_location`.

## Реализация

[`sql/03_status_trigger.sql`](../sql/03_status_trigger.sql):

- `refresh_location_status(location_id)` определяет фактический состав места тремя `EXISTS` и записывает статусы тремя `UPDATE` с `CASE`. Результат зависит только от состава, а не от истории перемещений.
- `trg_update_status()` вызывает пересчёт для нового места и, если место сменилось, для прежнего. `DELETE` пересчитывает место удалённого участника.
- Триггеры объявлены как `AFTER INSERT OR DELETE OR UPDATE OF current_location`, поэтому собственные обновления `status` их не запускают и рекурсии нет.

Сценарии проверены в [`sql/05_tests.sql`](../sql/05_tests.sql): бегство к пингвинам, погоня, расхождение группы, уход существа, удаление участника, а также ограничения `CHECK` и `UNIQUE`.
